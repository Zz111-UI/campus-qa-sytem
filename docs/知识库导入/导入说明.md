## 一、「导入」是什么意思

项目里有个 `data/knowledge_base.json`，存着一堆**问答条目**。每条长这样：

```
{ id, category, question, answer, source, doc_name, scope, updated_at, verified, keywords }
```

用户提问时的流程是：

```
用户提问 → 后台用「关键词命中 + 整句相似度」在条目里检索 → 命中条目的 answer 作答 + 挂来源卡片
```

所以「把手册导入」= **把手册内容拆成一条条问答，写进这个 json**。
程序本身不需要改（本次除了两处小修复，见第五节）。

## 五、程序侧的两处小修复（必要）

导入后实测发现，光有数据还不够——有两处老逻辑会把新条目挡住：

### 1）游客问政策性问题被"请先登录"拦住（`app.py`）

**现象**：游客问「转专业需要什么条件」，系统返回"选课推荐与学业规划需要结合你的专业、年级等画像信息，请先注册 / 登录"，根本走不到知识库。

**原因**：问题被分诊成 `study`（学业规划），而游客问学业规划会直接引导登录——但转专业条件、处分标准这类**政策性问题属于公开信息，不依赖用户画像**。

**修复**：知识库能强命中时（关键词命中≥2，或命中≥1 且整句相似度≥0.45），改走知识库直接回答。
个性化选课推荐仍会正常引导登录（实测「我想保研怎么选课」仍要求登录，原设计未被破坏）。

### 2）来源卡片重复（`advisor.py`）

**现象**：问「考试作弊会有什么处分」会挂 3 张一模一样的「本科生手册·学生纪律处分规定」卡片。

**原因**：检索命中 3 条不同条目，但它们属于同一章节。

**修复**：`build_source_cards` 按出处去重，同一章节只保留一张卡片。

> 改动前的原文件在最初提交的压缩包里，如需还原，直接替换这两个文件即可。

## 六、验证结果

用「用户可能怎么问」的口语句子做批量检索测试（脚本在 `脚本/` 目录）：

| 轮次 | 用例数 | Top1 命中率 | 说明 |
|---|---|---|---|
| 第一轮测试（生活部分） | 71 | 85.9% → **94.4%** | 补关键词后无命中清零 |
| 第二轮测试（含回归） | **126** | **100%** | 生活 + 学籍教务全部用例 |
| 游客可答性检查 | 126 | **通过** | 无问法会被"请先登录"拦截 |

第二轮修复的 6 处漏检/竞争：

| 用户问法 | 原因 | 修复 |
|---|---|---|
| 学费能减免吗 | 关键词只有"学费减免"，中间夹了"能" | 补 `学费/减免/能减免吗` |
| 毕业要满足什么条件 | 被"体测"条目抢走 | 补 `毕业/毕业标准` |
| 期末成绩占多少 | 被"成绩什么时候能查"抢走 | 补 `期末成绩/成绩占` |
| 什么情况会被取消考试资格 | 只有"取消考核资格" | 补 `取消考试资格/考试资格` |
| 宿舍用违章电器什么处分 | 与"哪些电器不能用"打平 | 补 `什么处分` |
| 怎么续借 | 被"图书馆网址"条目抢走 | 补 `怎么续借/能续借吗` |

## 八、已知边界 / 后续可做

1. **保研、考研类问题走的是项目专用模块**，不是知识库。问「保研需要什么条件」返回的是
   「保研四通道总览」（来自校发文件，内容比知识库条目更细），两条路径并存、不冲突。
2. **个性化问题仍会引导登录**：如「我想保研怎么选课」「选课什么时候开始」——
   这类需要专业画像，属于原产品的设计意图，未改动。
3. **手册第 11 章的电子资源违规下载处理条款**只在长答案里带过，如需可单独拆条。
4. **手册里的电话、收费标准是 2025 级口径**，界面上建议继续保留「以学校最新通知为准」的提示。
